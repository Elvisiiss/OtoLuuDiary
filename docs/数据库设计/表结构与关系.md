# 数据库设计说明

## 基本信息

- **数据库名**: `otoluudiary`
- **字符集**: `utf8mb4`
- **引擎**: `InnoDB`
- **连接**: `jdbc:mysql://110.42.193.119:31101/otoluudiary`

## 表清单

| 表名 | 说明 | 关联 |
|------|------|------|
| `user` | 用户表 | — |
| `diary` | 日记表 | `diary.user_id` → `user.id` |

## 表关系

```
user (1) ──── (N) diary
     一个用户有多篇日记
     diary.user_id 外键关联 user.id
```

| 规范 | 示例 |
|------|------|
| 字段名全小写，单词间下划线分隔 | `diary_date`、`created_at` |
| 主键统一用 `id`，UUID 格式 VARCHAR(36) | `a1b2c3d4-...` |
| 时间统一用 BIGINT 毫秒时间戳 | `1725993600000` |
| JSON 字段用 MySQL JSON 类型 | `tags` 列 |

## 特殊逻辑：diary_date 字段

`diary_date` 是日记的"归属日期"，与创建时间 `created_at` 解耦。

**默认规则（凌晨4:00分界线）**：

```
当前时间 < 04:00 → diary_date = 昨天 00:00:00
当前时间 ≥ 04:00 → diary_date = 今天 00:00:00
```

- 前端优先计算并发送
- 后端兜底计算（使用服务器本地时区）
- 存储为当天 00:00:00 的毫秒时间戳
- 用户可在创建/编辑时手动选择日期
- 列表按 `COALESCE(diary_date, created_at)` 排序

## 旧数据兼容

已有的无 `diary_date` 的日记记录，列表页自动回退使用 `created_at` 显示和排序。
